# StoreKit Configuration (local IAP testing)

`InnerMap.storekit` is an Xcode **StoreKit Configuration file**: a local, offline model of the real
App Store Connect products (`innermap_monthly` — $24.99/mo with a 1-week free trial, in the
"Inner Map Membership" subscription group — and the `innermap_topup_10` consumable at $19.99; the
`_10` in that ID is a known misnomer, the price really is $19.99). With it enabled, StoreKit serves
those products from this file, so the paywall can be built, run and purchased against **with no App
Store / sandbox connection and no signed-in Apple ID**.

## Enable it

1. Open the generated project: `ios/InnerMap.xcworkspace` (see the prebuild note below).
2. **Product > Scheme > Edit Scheme… > Run > Options > StoreKit Configuration**
3. Pick `InnerMap.storekit` (add the file to the project first via *File > Add Files to "InnerMap"…*
   if it does not appear in the dropdown — add it as a **reference**, do not copy it into `ios/`).
4. Run from Xcode. Manage the fake transactions under **Debug > StoreKit**
   (Manage Transactions / Subscriptions) — approve, refund, expire, reset intro-offer eligibility.

## Disable it to test the real thing

Set that same dropdown back to **None** before testing against the **real StoreKit sandbox**
(sandbox Apple ID, real App Store Connect products) or anything that talks to a live backend.
While a StoreKit Configuration file is active the purchases are local and never reach Apple —
so App Store Connect, RevenueCat and our server-side receipt/webhook path see nothing. If a
purchase "succeeds" but entitlements never appear server-side, check this setting first.

## It does NOT survive a prebuild

This repo is managed / prebuild-generated: `ios/` and `android/` are gitignored and regenerated by
`npx expo prebuild` (and on every EAS build). The scheme setting lives in
`ios/<Scheme>.xcodeproj/xcshareddata/xcschemes/<Scheme>.xcscheme`, which is regenerated and therefore
wiped. This file lives **outside `ios/`** on purpose so it survives; the scheme selection (steps 2–3
above) must be **re-done after every `expo prebuild --clean`**. It also has no effect on EAS builds —
it is a local, run-from-Xcode-only tool.
